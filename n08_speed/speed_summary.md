# 목표 7: 쌍극자 스캔이 정말 빠른지 (신호 1개당 계산 시간)

스크립트: `speed_scan.py` · 결과: `speed_scan_thr8.csv`(본 결과), `speed_scan_thr1.csv`, `speed_scan_setup_thr*.csv` · 2026-11-24 연세대 서버2, GPU 0번(RTX 3080 Ti), 가상환경 autumn

## 주의할 점 (먼저)

1. **실제 뇌 모양 머리가 아님.** `week09/cache_real`이 이 서버에 없어 5,124곳 × C채널 × 3 크기의 무작위 리드필드로 쟀다. 이 계산들은 행렬 크기에만 시간이 좌우되므로 값이 달라도 시간은 거의 같을 것으로 보이지만, 캐시를 복사한 뒤 다시 돌려 확인해야 한다(스크립트가 캐시가 있으면 자동으로 사용).
2. **256채널은 캐시에도 없음** (캐시는 64채널). 캐시가 있어도 256채널은 64채널을 섞어 늘린 대체 행렬이다.
3. 학습 모델 가중치는 크기만 같은 임의 값이다(정확도는 재지 않음).
4. 서버 공유 중(다른 작업 3개가 CPU 사용) → CPU 숫자는 ±2배 정도 흔들린다. 기본 스레드 설정에서는 OpenBLAS 스레드 대기로 호출당 약 6 ms가 붙는 이상값이 나와(`log_speed_scan_default_threads.txt`) 스레드를 8개로 고정한 결과를 본 결과로 쓴다.
5. 여기서 "쌍극자 스캔"은 5,124곳 격자를 모두 훑는 계산이다. 비선형 최적화로 위치를 다듬는 진짜 dipole fit은 이보다 느리다.
6. GPU 시간은 CPU 메모리 → GPU → 답을 CPU로 받기까지 전송을 포함한다. CPU와 GPU의 답(위치 번호)은 모든 조건에서 100% 같았다.

## 읽는 법

- **신호 1개씩(배치 1)**: 세 방법 모두 0.03~0.4 ms. 실제 계산보다 함수 호출·GPU 전송 같은 고정 비용이 대부분이라 차이가 작고, GPU는 오히려 느리거나 비슷하다. 이 경우 학습 모델이 가장 느린데, sklearn `predict`와 KD-tree 검색의 고정 비용 때문이다.
- **묶어서(배치 100, 1000) CPU**: 쌍극자 스캔은 약 0.07~0.17 ms로 줄지 않는다(5,124곳 × 3방향 = 15,372개 값을 신호마다 만들어 더하고 비교해야 함). sLORETA와 학습 모델은 0.003~0.02 ms로, 스캔이 **약 10~30배 느리다**.
- **묶어서 GPU**: 셋 다 신호당 0.0002~0.005 ms. 쌍극자 스캔도 1,000개 묶음이면 신호당 약 0.001 ms(1 µs)라서 **GPU를 쓰면 스캔도 충분히 빠르다.** 학습 모델과의 차이는 1~2배 이내.
- 이전 측정(CPU, 스캔 0.46 ms vs 학습 모델 0.036 ms)과 같은 방향이지만, "학습 모델이 13배 빠르다"는 CPU에서만 맞는 말이고 GPU에서는 거의 사라진다. **속도를 학습 모델의 장점으로 내세우기는 어렵다.**
- GPU의 스캔 QR 준비 시간(약 120 ms)은 작은 행렬 5,124개를 따로 분해하는 torch 함수의 고정 비용이다. 몽타주당 한 번이라 신호 수가 많으면 무시할 수 있다.
