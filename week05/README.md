## 어댑터 (adapter.py)

몽타주마다 자기 leadfield로 MNE 역연산자 K를 만들고, 평균 기준으로 바꾼 입력 y에 곱해 7,498곳의 source 지도 x = Ky를 얻는다.
모든 몽타주가 공유하는 PCA 기저 B(256 x 7,498)에 투영해서 256차원 벡터로 만들고 MLP에 넣는다.
채널이 몇 개든 입력 크기가 같아지고, 전극이 어디 붙었는지는 leadfield를 통해 들어간다.
sLORETA 어댑터는 K에 sLORETA 정규화를 곱한 것이다. 입력 벡터는 모두 크기를 1로 맞췄다 (세기 정보 제거, 표현만 비교).
비교 대상인 마스크 방식도 같은 정규화를 적용했다.

학습 두 가지
- C1 (엄격): 학습에 무작위 채널 부분집합(3~64개)만 사용. 이름 있는 몽타주 5종은 처음 보는 몽타주
- C2: 학습 샘플의 절반은 이름 있는 몽타주 5종, 절반은 무작위 부분집합

테스트는 정답 머리(전도도 0.010, 전극 위치 오차 5 mm), 방향 0~30도 무작위, SNR 10 dB(64채널 기준).
새 무작위 부분집합은 학습에 쓰지 않은 20개를 채널 수 구간별로 평가.

## 해석

- 처음 보는 몽타주에서 어댑터가 마스크보다 크게 낫다. 32채널은 21.8 → 12.1 mm, 16채널은 28.5 → 17.9 mm (sLORETA 어댑터). 마스크 방식은 학습에서 본 몽타주에만 강하고(C2에서 32채널 13.2 mm), 모르는 부분집합에서는 급격히 무너진다.
- 64/32/16채널에서는 어댑터가 학습에 이름 있는 몽타주가 있든 없든 비슷하다 (C1과 C2 차이 1 mm 이하, 16채널 sLORETA 어댑터는 17.9 vs 16.9). 몽타주를 외우는 것보다 입력 표현이 차이를 흡수한다는 쪽의 증거이다. 단 이마 몽타주는 예외로, 학습에서 못 본 C1이 C2보다 6~32 mm 나쁘다 (sLORETA 어댑터 이마4 54.6 vs 48.7, MNE 어댑터 이마4 68.4 vs 48.8). 학습 분포 밖의 배치에는 어댑터도 일반화하지 못한다.
- 그러나 몽타주별로 따로 학습한 MLP보다는 여전히 나쁘다: 64채널 9.6 vs 8.5, 32채널 12.1 vs 11.2, 16채널 17.9 vs 16.4 mm. 모델 1개의 대가는 1~1.5 mm 정도.
- sLORETA 정규화 어댑터가 MNE 어댑터보다 대체로 낫지만 차이는 0.5~1.3 mm 수준이고 16채널은 MNE 어댑터가 근소하게 낫다(17.6 vs 17.9). 시드 2개로는 순서를 단정하지 않는다. 이마 2채널 C1에서는 MNE 어댑터가 83.6 mm로 크게 무너졌다.
- 이마 2~4채널은 해결하지 못했다. 학습에서 본 경우(C2)에도 48~51 mm로 항상 중심을 답하는 값(52.5 mm)과 비슷하다. C1에서는 54~84 mm로 그보다 나쁘다. 채널 수 문제를 "해결"했다고 쓰면 안 된다.
- 채널 3~8개 무작위 부분집합은 모든 방법이 43~57 mm이다. 정보량 자체의 한계로 보이나, 이 실험이 한계를 증명하지는 않는다.

## 한계 (읽을 때 주의)

- 머리는 sample 1명이다. 어댑터가 "새 머리"에도 통하는지는 이 실험으로 알 수 없다. 오히려 어댑터는 모델 머리의 leadfield를 쓰므로, 머리가 달라지면 이 이점이 어떻게 변할지 모른다. 교수님 메모의 "리드필드를 입력으로 넣으면 잘 된다"는 이 실험과는 다른 설정이며, 여기서 검증하지 않았다.
- 어댑터의 PCA 기저는 이 머리의 source 지도로 만들었다. 다른 머리에서는 기저를 다시 만들어야 하는지 확인하지 않았다.
- 비교 대상인 sLORETA는 튜닝하지 않았다 (lambda^2 = 1/9, depth weighting 없음).
- 어댑터는 7,498 x k 크기의 역연산자를 몽타주마다 계산한다. 실제 사용에서 전극 위치를 몰라 leadfield를 못 만드는 경우는 다루지 않았다.
- 점 source 1개, 시간 정보 없음. 멀티소스와 시계열(Week 4-2)은 합치지 않았다.
- 시드 2개. 1 mm 안팎의 차이는 해석하지 않는다.

## build_subject_forward.py

피험자 한 명의 FreeSurfer 폴더에서 BEM, source space, 전극 위치로 리드필드 (채널 x source x 3)를 만들어 npz로 저장한다.
sample 피험자 + biosemi64로 (64, 7498, 3) 배열이 만들어지는 것까지 확인했다. 다른 머리에서는 실행해 보지 않았다.
- T1만 있는 MRI(예: IXI)는 FreeSurfer recon-all을 먼저 해야 한다. 이 코드는 하지 않는다.
- MRI-전극 정합(trans)은 인자로 받는다. 피험자마다 만들어야 한다.

## 다중 머리 실험 (heads.py + multihead.py)

### 머리를 어떻게 만들었나

실제 MRI가 아직 없어서, sample 머리 하나를 변형해 "서로 다른 머리"를 만들었다.
BEM 표면 3개, 피질 source 위치·방향, 전극 위치에 같은 공간 변형을 적용한다.

- 보통 변형 (17개): 축별 크기 0.88~1.12배, 기울임 최대 0.04, 매끄러운 국소 변형(폭 35 mm, 최대 8 mm), 두개골 두께 -1.5~+2.0 mm
- 강한 변형 (6개, 평가에만 사용): 크기 0.80~1.20배, 국소 변형 최대 14 mm(폭 30 mm), 두께 -1.5~+3.0 mm
- 머리마다 정답 forward(두개골 전도도 0.005~0.015 무작위, 전극 위치 오차 5 mm)와 모델 forward(0.006, 오차 없음)를 따로 계산
- 기준 머리와의 피질 vertex 위치 차이: 보통 변형 평균 4.6 mm (3.0~6.6), 강한 변형 평균 6.7 mm (5.7~8.0)
- 피질 vertex 번호는 모든 머리에서 같다 (같은 7,498곳). 그래서 "같은 vertex = 같은 해부학적 위치"

검산: 기준 머리와 각 머리의 리드필드(수직 성분) 상관은 보통 변형 평균 0.995, 강한 변형 평균 0.989이다.
같은 머리에서 전도도·전극 위치만 다를 때(정답 vs 모델 forward)는 평균 0.986이다.
즉 이 변형이 만드는 머리 차이는 전도도 불일치보다 작다. 실제 사람 사이 차이는 훨씬 클 것이다.

### 비교한 방법 (모두 64채널, 단일 쌍극자, 방향 0~30도, SNR 10 dB)

| 방법 | 머리 정보를 쓰는 방식 |
| --- | --- |
| sLORETA (기준 머리) | 모든 머리에 sample 원래 머리의 리드필드 사용 (개인 MRI가 없는 경우) |
| sLORETA (자기 머리) | 그 머리의 리드필드 사용 |
| MLP 센서만 | 머리 정보 없음 |
| MLP 센서 + 머리 벡터 | 리드필드를 16차원으로 줄인 요약 벡터를 입력 옆에 붙임 (세미나의 global MRI 벡터와 같은 계열) |
| 어댑터 (기준 머리 리드필드) | 5-1의 sLORETA 어댑터를 기준 머리 리드필드로 |
| 어댑터 (자기 머리 리드필드) | 그 머리의 리드필드로 만든 역연산자로 피질 지도를 만든 뒤 입력 |

머리 벡터는 학습 머리들의 표준편차로만 크기를 맞춘다 (평가 머리 정보가 새지 않게).
학습 샘플 총수는 머리 수와 무관하게 30,000개로 고정했다 (데이터 양이 아니라 머리 다양성의 효과를 보기 위함).
출력은 기준 머리 좌표로 예측하고, 가장 가까운 vertex를 찾아 그 머리에서의 실제 위치로 오차를 잰다.

### 해석

- <b>머리 요약 벡터를 입력에 붙이면 새 머리에서 무너진다.</b> 학습 머리에서는 9.1 mm인데 새 머리에서는 26.4~39.4 mm이다. 학습 머리가 3개일 때 가장 나쁘고 12개로 늘리면 줄지만 여전히 약 3배 나쁘다. 모델이 머리 벡터를 "어느 머리인지" 구분하는 표지로 쓰고, 처음 보는 값에서 엉뚱하게 외삽하는 것으로 보인다. 세미나에서 본 global MRI 벡터의 신원 지름길과 같은 현상이다. 다만 이 결과는 내가 만든 한 가지 요약 방식(고정 무작위 투영 16차원)에 대한 것이다. 머리 50개 이상, 정규화나 dropout을 쓰면 달라질 수 있다.
- <b>자기 머리 리드필드를 쓰는 어댑터는 새 머리에서도 안정적이다.</b> 새 머리 9.2 mm, 강한 변형 머리 9.1 mm로 거의 안 변한다. 같은 조건에서 기준 머리 리드필드를 쓰면 9.7 → 9.9 mm, 센서만 쓰면 9.3 → 9.7 mm로 조금씩 나빠진다. 고전 방법에서도 같은 방향이다: sLORETA의 자기 머리 vs 기준 머리 차이가 1.0 mm에서 1.8 mm로 커진다.
- 그러나 차이 자체는 작다 (0.5~0.8 mm). 이 변형 머리들의 차이가 전도도 불일치보다 작기 때문으로 보인다. "리드필드 입력이 더 잘 된다"는 메모에 대해서는, <b>넣는 방식에 따라 정반대 결과가 나온다</b>는 것이 이번 실험의 핵심이다. 요약 벡터로 넣으면 해롭고, 역연산자(물리)를 거쳐 넣으면 안정적이다.
- 학습 머리 수(1→12)는 새 머리 성능을 거의 바꾸지 않았다 (센서만 9.2~9.4 mm). 이것을 "머리 50개가 필요 없다"로 읽으면 안 된다. 이 변형이 너무 약해서 머리 수의 효과가 드러나지 않은 것으로 보는 것이 맞다.
- E2: 몽타주와 머리가 둘 다 처음일 때도 어댑터가 마스크보다 크게 낫다 (32채널 12.8 vs 21.4 mm). 이때는 자기 머리와 기준 머리 리드필드 차이가 없었다. 몽타주 차이가 머리 차이보다 훨씬 커서 묻힌 것으로 보인다.
- 16채널에서 어댑터는 평균 오차는 sLORETA보다 작지만(18.5 vs 21.5 mm) 10 mm 이내 비율은 낮다(17 vs 24%). sLORETA는 맞을 때 정확히 맞고 틀릴 때 크게 틀리는 반면, 어댑터는 고르게 중간 정도로 맞힌다. 실제 데이터에서 "source 1개를 가장 잘" 맞히는 기준이 무엇이냐에 따라 평가가 달라진다.

### 한계

- <b>실제 다른 사람의 MRI가 아니다.</b> 크기·모양·두께만 바꿨고, 주름 모양과 피질 배치는 모두 같다. vertex 대응도 실제 피험자 사이보다 훨씬 깔끔하다. 실제 MRI에서는 차이가 더 커질 것이고, 어떤 방향으로 바뀔지는 이 실험이 말해 주지 않는다.
- 학습 머리 크기가 우연히 대부분 1.0배 이하였다 (0.90~1.00). 평가 머리 중 head014(1.03배), head017(1.10배)은 학습 범위 밖이다.
- 머리 벡터는 한 가지 방식만 시험했다.
- 출력을 기준 머리 좌표로 예측한 뒤 가장 가까운 vertex로 바꾸므로, 피질 간격(약 5 mm) 수준의 양자화 오차가 학습 방법 모두에 들어간다.
- 시드 2개, 평가 머리 6개.

## 라벨 없는 기록으로 적응 + 전극 위치 오차 (heads_variants.py + adapt.py)

11/4 메모의 "그 사람의 EEG 1분으로 빠르게 어댑테이션"을, 두개골 전도도를 고르는 문제로 구체화했다.
전도도는 사람마다 다르고 MRI로 알 수 없으며, 지금까지 모델은 항상 0.006을 썼다 (평가 머리의 진짜 값은 0.0072~0.0146).

방법
1. 평가 머리마다 정답 위치를 모르는 사건 N개를 받는다 (N=200을 "1분 기록"으로 가정. 실제로는 스파이크나 유발 반응처럼 쌍극자 하나로 설명되는 사건을 골라야 함)
2. 후보 전도도 6개(0.004, 0.006, 0.008, 0.010, 0.012, 0.015)의 리드필드마다, 사건을 쌍극자 하나로 얼마나 잘 설명하는지(GOF) 평균을 낸다

$$\mathrm{GOF}(y) = \max_i \frac{\lVert Q_i^\top y \rVert^2}{\lVert y \rVert^2}$$

   ($Q_i$: i번째 위치의 3방향 리드필드 열의 정규직교 기저, 평균 기준 적용)
3. 평균 GOF가 가장 큰 전도도를 고르고, 그 리드필드로 sLORETA와 어댑터의 역연산자를 다시 만든다. 어댑터 모델은 다시 학습하지 않는다

결과 E4 (시드 2개 평균, 평가 머리 6개, 전극 오차 5 mm)

| 사건 수 | 진짜에 가장 가까운 후보를 고른 비율 | 한 칸 이내 |
| --- | --- | --- |
| 10 | 42% | 83% |
| 50 | 50% | 92% |
| 200 | 75% | 100% |

| 방법 | 기본 전도도 0.006 | 적응 (사건 200개) | 상한 (진짜에 가장 가까운 후보) |
| --- | --- | --- | --- |
| sLORETA (자기 머리) | 14.2 / 44 | 13.5 / 46 | 13.6 / 46 |
| 어댑터 (자기 머리) | 9.2 / 61 | 8.8 / 65 | 8.7 / 66 |
| MLP 센서만 (적응 불가) | 9.6 / 58 | - | - |

결과 E5: 전극 위치 오차 (모델은 표준 위치, 전도도 0.006)

| 오차 | sLORETA (자기 머리) | MLP 센서만 | 어댑터 (자기 머리) |
| --- | --- | --- | --- |
| 0 mm | 11.2 / 58 | 9.1 / 62 | 8.7 / 65 |

| 15 mm | 26.2 / 15 | 13.2 / 37 | 13.1 / 37 |

해석
- 라벨 없이도 전도도를 고를 수 있었다. 사건 200개면 항상 한 칸 이내였고, 적응한 결과가 상한과 같았다. 사건 10개로는 부족하다
- 어댑터는 다시 학습하지 않고 리드필드만 바꿔 끼워서 9.2 → 8.8 mm로 좋아졌다. "센서만" 모델은 이런 식으로 적응할 방법이 없다. 이 점이 어댑터 구조의 실용적 장점이다
- 다만 전도도 적응의 이득은 0.4~0.7 mm로 작다. 반면 전극 위치 오차는 훨씬 크게 영향을 준다: sLORETA는 0 → 5 mm 오차에서 11.2 → 14.3 mm로 나빠진다. 실제 데이터에서는 전도도보다 전극 위치를 정확히 아는 것이 더 중요할 수 있다
- 학습 모델(센서만, 어댑터)은 전극 오차에 훨씬 덜 민감하다 (15 mm 오차에서도 13 mm). 학습 때 전극 오차를 넣지 않았는데도 그렇다. 이유는 확인하지 않았다
- 자동 정합(sample에서 전극-두피 거리 중앙값 5.6 mm) 수준의 오차라면 어댑터는 약 0.5 mm 손해로 버틴다

한계
- 사건이 모두 쌍극자 하나에서 나온다고 가정했다. 실제 1분 기록의 대부분은 배경 활동이라 그대로는 GOF가 의미 없다. 사건 고르기(스파이크 검출, 평균 유발 반응)가 앞에 붙어야 한다
- 후보 전도도 간격이 넓다 (0.002~0.003). 진짜 값이 후보 사이에 있다
- 전극 오차 방향은 머리마다 하나로 고정하고 크기만 바꿨다
- 변형 머리, 평가 머리 6개, 시드 2개

## OASIS-3로 옮기기 (oasis_pipeline.py + oasis_split.py)

연구실은 OASIS-3를 쓴다. OASIS-3 약관(DUA) 때문에 지킬 것:
- 데이터는 승인된 사용자만 접근 가능. 협력자도 각자 신청해야 함. 학부연구생이 쓰려면 본인 신청이 필요한지 교수님께 확인
- 원본 MRI와 두피 표면(얼굴 복원 가능)은 연구실 서버 밖으로 옮기지 않음. GitHub에는 코드와 집계 결과만
- 논문·발표에는 DUA의 감사 문구와 OASIS-3 논문(doi:10.1101/2019.12.13.19014902) 인용

흐름 (연구실 서버에서)
1. `oasis_split.py`: 세션 표 → 피험자당 1세션 → 층(나이 × CDR × 자기장) → 평가 피험자를 먼저 떼고 학습 50명을 층마다 고르게 → `split.json`
2. 고른 피험자마다 `oasis_pipeline.py`: BEM 표면(없으면 watershed, FreeSurfer 필요) → fsaverage ico-4 대응 source 5,124곳 → 표준 몽타주 자동 정합 → 정답/모델 forward → `<피험자>.npz`
3. `SPLIT=split.json python week05/multihead.py` → 같은 E1/E2 실험이 실제 머리로 돌아감

sample로 확인한 것
- 끝까지 실행됨 (약 2.5분/명). source 5,124곳 중 5,119곳 유효 (5곳은 두개골 안쪽 면 밖)
- 자동 정합 후 전극-두피 거리 중앙값 5.6 mm, 최대 14.2 mm (전극은 forward 계산 때 두피에 투영됨)
- 대응표 검증: `mne.morph_source_spaces` 결과는 정점 번호가 피험자 순서로 정렬돼 fsaverage 순서 대응이 사라진다 (같은 번호끼리 비교하면 최대 120 mm 차이). 그래서 구면 정합으로 대응표를 직접 만들었고, MNE 결과와 정점 집합이 99.8~99.96% 일치함을 확인
- `multihead.py`의 SPLIT 모드가 이 출력 형식을 읽어 끝까지 도는 것 (같은 sample을 여러 번 넣은 동작 확인용)

확인 못 한 것
- OASIS-3 피험자로 실행 (데이터 접근 없음). OASIS-3 FreeSurfer 결과(v5.x)에 BEM 표면이 있는지 모름
- 고령·위축 뇌에서 3층 BEM의 오차 (CSF 층이 두꺼워짐)
- 자동 정합의 정확도 (실제 전극 측정 위치가 없음)
- `oasis_split.py`의 열 이름: OASIS-3 표의 실제 열 이름에 맞춰 인자로 지정해야 함

| 공통 source | 원래 머리 7,498곳을 모든 머리에 고정 | 머리마다 같은 번호 = 같은 위치가 되도록 |

### 5-5 적응 + 전극 오차

| 파라미터 | 값 | 근거 |

## 실행 시간

작업 환경: 클라우드 리눅스, CPU 2코어, 메모리 8 GB, GPU 없음. MacBook Air가 아님. 아래는 계산 시간만이고 코드 작성·분석 시간은 뺐다.

| 단계 | 내용 | 걸린 시간 (실제 경과) |
| --- | --- | --- |
| 5-1 | 빠른 확인 2.5분 + 시드 0 10분 + 시드 1 13분 | 약 26분 |
| 5-3 머리 만들기 | 원래 머리 4.6분 + 보통 변형 17개 29분 (2개 병렬, 머리당 2.2\~3.2분) + 강한 변형 6개 7분 (2개 병렬) | 약 41분 |
| 5-3 실험 | 시드 0 11분 + 시드 1 10.5분 | 약 22분 |
| 5-5 후보 리드필드 | 평가 머리 6개 × (후보 전도도 6개 + 전극 오차 4단계) (2개 병렬, 머리당 9\~10.5분) | 약 29분 |
| 5-5 실험 | 시드 0 4분 + 시드 1 4분 | 약 8분 |
| OASIS 코드 확인 | sample 1명 2회 (대응표 수정 전후) | 약 5분 |
| <b>합계 (최종 결과)</b> | | <b>약 2시간 10분</b> |
| 버리고 다시 돌린 것 | 메모리 부족으로 죽은 실행, 방향 기준 버그로 다시 만든 머리, 머리 벡터 정규화 수정 전 5-3 실행 등 | 약 55분 |

병렬로 돌린 단계가 있어 CPU 사용 시간 합계는 이보다 길다.
OASIS-3 70명으로 돌리면 forward만 머리당 약 2.5분이라, 2코어 환경 기준 약 1.5시간 (연구실 서버에서는 더 짧을 것).
